This is a common pharmacy inventory problem — you need multi-level unit-of-measure (UoM) handling, since medicines are bought in bulk packs but sold in smaller units (or as whole units, like syrup bottles).
The core concept to explain to your agent:
Each medicine has a base/smallest sellable unit (tablet, capsule, ml, bottle, etc.)
Each medicine also has packaging levels with conversion factors:
Box → Strips → Tablets (e.g., 1 box = 10 strips, 1 strip = 10 tablets = 100 tablets total)
Bottle → itself is the unit (1 bottle = 1 sellable unit, no breakdown)
Stock is tracked internally at the base unit level (e.g., total tablets), but purchases/display can happen at any packaging level
When selling, the system converts and deducts from base stock (e.g., sell 5 tablets → deduct 5 from the 100 total)
Prompt you can give your agent to fix this:
"Update the inventory system to support multi-level packaging and unit conversion, since medicines aren't uniform units.
Requirements:
Add a units or packaging table linked to each medicine, with fields: unit_name (e.g., box, strip, tablet, bottle, ml), conversion_factor (how many base units it equals), and is_base_unit (boolean)
Each medicine has ONE base unit (e.g., tablet for tablets, ml for syrup, or bottle if sold whole)
Stock quantity is always stored internally in base units
When adding stock (purchase), allow input in any defined packaging level (e.g., '5 boxes') and auto-convert to base units for storage
When selling, allow selection of unit (e.g., 'sell 2 strips' or 'sell 10 tablets') and deduct the correct base-unit amount from stock
Display available stock in the most sensible format (e.g., '3 boxes, 2 strips, 5 tablets' instead of just '325 tablets')
For non-divisible items like syrup bottles, the base unit IS the bottle — no further breakdown needed
Example schema:
medicines: id, name, base_unit
medicine_units: id, medicine_id, unit_name, conversion_factor_to_base
inventory: medicine_id, quantity_in_base_units
Update the database schema, backend logic, and relevant frontend forms (add stock, sell/dispense, stock display) to reflect this."
